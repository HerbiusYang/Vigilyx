# 语义数据

这里维护语义词表和策略的唯一源码副本，沿用原有数据键名并在对应词表内增补：

| 文件 | 内容 |
| --- | --- |
| `context.json` | 请求、指令、否定、报告、动作、对象、引用、子句、角色和链接指针词表 |
| `scenarios.json` | 单声明场景策略、跨声明及跨来源场景候选策略 |
| `relations.json` | 勒索词表、勒索关系准入、凭据回传的 NLP 辅助准入策略 |
| `scan.json` | 正文选择和文风观察配置 |

数据继续使用 `version`、`description`、`lists` 和各条目的 `items` 格式。数据库层的 `embedded_module_data_seed()` 将这四个文件与共享种子合成为完整默认种子，数据库初始化与引擎无数据库时的默认加载使用同一个合成结果。

数据库配置合并、管理员增删覆盖、注册表热更新及语义缓存失效继续使用现有机制。不同源码文件不能拥有同名数据键；合成器会拒绝重复定义，避免一处修改被另一份配置覆盖。

共享域名、其他检测模块词表继续位于 `shared/schemas/engine_module_data_seed.json`。场景测试样本仍在原测试目录，本目录只存放运行时词表和策略。

## 中文词条维护

中文提示词是本地语义提取线索，不是大模型提示词或训练权重。请求、指令、否定、报告、动作和对象分别维护；例如“劳烦您回传动态口令”可以组合为请求、回传动作和凭据对象，“无需回传动态口令”则应保留为局部反动作。

本次增补涵盖礼貌请求、即时指令、局部否定、明确案例转述、凭据与个人资料、账户访问、收款信息和站外联系。词条追加到原列表，原有场景 ID、关系准入和计分阈值保持不变。`scenarios.json` 同步扩展已有场景的动作和对象集合，仍要求同一有界声明中的当前收件人请求；场景本身只输出观察，不单独构成恶意证据。

维护时注意：

- 新动作和对象必须先进入 `context.json`，再加入适用的场景条件，避免出现提取器无法产出的场景词条。
- 不将“点击”“上传”“二维码”等孤立词直接当作账户或凭据请求。二维码本身不证明用途，也不证明实际链接或目标归属。
- 第一人称“我们希望您……”只补入明确的收件人指向；原有引用、转述、否定和局部作用域约束继续适用。
- 新增 HTML 按钮词仍需绑定自身实际观测到的链接或表单载体；正文提及不能借用其他按钮的链接，链接可达也不代表归属可信。
- `policy.rs` 的中文回归用例覆盖直接请求、否定、引用、案例报告、第一人称指向、独立混合请求和按钮链接归属；用例源码已补充，尚未运行。
