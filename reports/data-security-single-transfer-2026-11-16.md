# 数据安全金融单条策略与深度验证

## 策略边界

本次按“单条敏感发送即告警”的产品要求整改：检测到敏感发送/上传且业务授权尚未核实时，从第一条生成风险事件。匹配本身不代表违法，也不证明成功投递。当前系统没有经核验的业务授权登记，事件明确标记 `authorization_status=unverified`、`legal_assessment=not_determined`。

- 4级候选的鉴别凭证、CVV、生物鉴别信息：单条 Critical。
- 3级候选的个人身份、联系方式、金融账户等：单条 High。卡号本身不等同于 CVV/口令；OTP 与账户信息组合可提升至4级。
- 草稿保存是敏感内容观察，单独展示，不进入外发批量和发送频次累计。
- 公开 SWIFT/BIC 单独出现不触发敏感外发事件；其他敏感信息、文件伪装与检测覆盖不足仍独立检查。
- 50/500条是产品附加批量告警阈值，不是监管允许发送的数量。当前累计只覆盖已观察的 HTTP 传输，状态保存在进程内，重启会重置。
- JR/T 0197-2020 的1—5级与 JR/T 0171-2020 的个人金融信息 C1—C3 分开。UI 显示检测候选级别，最终以机构审批目录和影响评估为准。5级不能直接标注为国家秘密。
- 旁路模式只能观察告警；MTA 的中继、隔离和拒绝结果与风险事件分别记录。

## 监管参考

以下规则需按机构、业务及数据适用范围判断，不存在适用于一切外发行为的统一“1条即违法”数量结论。

1. [中国人民银行业务领域数据安全管理办法](https://www.pbc.gov.cn/zhengwugongkai/attachDir/2025/11/2025111915275027791.pdf)：审批留痕、高敏感数据保护、传输通道及对外提供约束（重点第12、17、20、21条）。
2. [银行保险机构数据安全管理办法，金规〔2024〕24号](https://app.www.gov.cn/govdata/gov/202412/29/523120/article.html)：分类分级、事前评估、必要授权、对外提供的适用同意/法定依据、鉴别信息保护与日志（第18、22、28、34、43、45条）。
3. [个人信息保护法](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)：合法性基础、委托/对外提供、敏感个人信息与影响评估（第13、21、23、28、29、55、56条）。
4. JR/T 0197-2020 与 JR/T 0171-2020：安全级别与个人金融信息类别为不同维度，不能把产品 C4/C3 及批量数量写成标准强制条款。

## 发现与修复

1. 旧检测只检查自发自收，普通收件人会漏掉。改为检查所有已识别的 Webmail 发送操作，并补齐 SMTP 邮件风险事件。
2. 同用户相同类别的一小时抑制及内容指纹会吞掉不同发送。改为会话与事件类型的稳定 ID，数据库唯一键处理重试；不同会话保留。
3. 底层手机号/邮箱存在至少3个不同值的隐藏门槛。移除此门槛，重复值仍去重计数。单条签名联系方式也是内容候选，需授权核查，不能直接称为泄露。
4. JSON/Form 的收发件人元数据不等于正文携带的个人信息。剔除传输信封元数据，正文、主题及未知业务内容继续扫描。
5. OWA/Coremail 共用接口必须有明确发送动作；草稿、自动保存及登录不得直接当作外发。
6. 大请求优先读取路径验证后、有大小上限的临时正文，避免只扫描预览而漏掉尾部。
7. 事件证据不复制高敏感鉴别值；请求体脱敏补齐 CVV 及 JSON 正文字符串中的凭据。
8. 前后端共用 `shared/schemas/data_security_policy.json`。移除旧 `jrt.rs`、`jrt_compliance.rs`、`self_send_detect.rs` 的实现及废弃去重代码；旧事件类型仅保留历史数据读取兼容。
9. 部署时查到会话表约8757万条，旧的每日保留清理执行一次性 `DELETE`，持续超过一小时；逐行触发器持有共享计数器锁，使新会话写入排队，并导致迁移锁超时。取消未完成清理后阻塞解除。改为每批最多200行、独立提交、跳过占用行，每批锁等待250ms、执行2秒上限；单次清理最多100批且30秒预算，剩余数据留待后续清理。部署迁移前在运行容器停止后，释放本数据库固定运行角色遗留的 PostgreSQL 连接，避免断连后仍执行的查询阻塞 DDL。
10. 补齐银行账号检测输出 `bank_account` 与策略的命名映射，旧 `bank_account_context` 名称仅作兼容。回归同时发现旧凭据规则把单独账号标识当作密码：将账号标识从鉴别秘密规则移出，金融账号仍独立检测为 High，账号与 OTP 组合为 Critical。修正中文凭据提取时把字节长度当作字符偏移的问题，短中文密码上下文仍能检出。补齐电子邮箱、文件检查覆盖及编码敏感数据等前端标签，避免显示翻译 key。
